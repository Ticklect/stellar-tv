# Security policy

## Supported versions

Security fixes are provided for the latest published version when maintainers can reproduce and address the issue. Older versions are unsupported. During preparation of `0.4.1`, the latest published tag remains `0.4.0`.

| Version                      | Supported   |
| ---------------------------- | ----------- |
| Latest published release/tag | Yes         |
| Older versions               | No          |
| Unreleased development code  | Best effort |

## Reporting a vulnerability

Do not open a public issue containing exploit details, credentials, cookies, signed media URLs, or other sensitive information.

This repository does not currently have GitHub private vulnerability reporting enabled and does not publish a private security email. Maintainers should enable **Settings → Security → Advanced Security → Private vulnerability reporting**. Once enabled, reporters should use **Security → Advisories → Report a vulnerability** in this repository.

Until private reporting is enabled, open a public issue containing only a request for a private security contact. Do not include vulnerability details in that issue. A maintainer can then arrange an appropriate private channel.

Include, privately:

- Affected module version and TV/Tizen/TizenBrew configuration
- Impact and prerequisites
- Reproduction steps or a minimal proof of concept
- Any suggested mitigation
- Whether the issue has been disclosed elsewhere

Please allow maintainers a reasonable opportunity to investigate and coordinate a fix before public disclosure. The project will acknowledge receipt, assess scope, prepare a fix when feasible, and credit reporters who want credit.
